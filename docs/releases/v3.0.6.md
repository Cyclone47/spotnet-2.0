# Spotnet 3.0.6: modern .NET, WebView2 spot pages, FTS5 search

This is the largest release since 3.0. The application moves off .NET Framework, the last page
rendered by the old Windows browser control is gone, and the search index is rebuilt on FTS5.

Everything below has been built and tested; **none of it has been exercised against a live news
server over a long session yet**. Treat this as the release where that testing starts.

## Changed

- **Runs on .NET 8.** Setup installs the .NET 8 Desktop Runtime if it is missing, the same way it
  installs WebView2, which is why the installer grew from 43 MB to 98 MB.
- **Spot pages render in WebView2.** The spot detail view and the comments inside it were the last
  users of the Windows WebBrowser/MSHTML control. That control, and the code around it, is removed.
- **Search uses FTS5.** The `search` and `comments` indexes migrate on first start, rebuilt from the
  spots themselves in one transaction. The spots are never touched, so a failed migration simply
  runs again next time. Startup says what it is doing while it runs.
- **The view modes moved into the menu.** Bewerken > Beeld now lists list, list with details and
  thumbnails. The three small buttons that used to sit beside the menu were clipped whenever the
  menu needed the space.
- **Dependencies.** Thirty-three vendored DLLs are gone. MahApps.Metro is on 2.4.11, MVVM Light and
  Starksoft.Aspen were replaced by the small pieces of them this application actually used, and the
  Xceed toolkit was dropped rather than upgraded into a licence that forbids public distribution.

## Fixed

- Stored values longer than sixteen characters decrypted truncated. The signing key is one of them.
- The initialization vector for the settings cipher was rejected outright on modern .NET, which
  stopped the application during startup.
- Setup left the previous version's files in place. Upgrading from a .NET Framework build left a
  second copy of SQLite in the program directory, and the first database query corrupted the
  process heap.
- Three assemblies packages ship per architecture never reached the installation, so opening a spot
  failed on a `System.Runtime.Caching` that was visible in the folder but unusable.
- The header parser silently produced nothing on modern .NET, because a Visual Basic helper it calls
  for every spot needs a code page .NET no longer registers by default.
- Filters saved with FTS4's `docid` are rewritten as they are read, so existing filters keep working.
- A database schema repair now records the version it wrote, instead of leaving migrations to run
  over tables already created in their final shape.

## Install or upgrade

Download **Spotnet-3.0-x64-Setup.exe** and run it under your usual Windows account. Setup upgrades an
existing installer-based Spotnet 3.0 installation, keeps the profile, makes a verified backup and
updates current-user shortcuts. It now also clears the previous version's binaries first.

Requires Windows 10/11 x64. Setup installs the .NET 8 Desktop Runtime and Microsoft Edge WebView2 if
they are missing. The package is **unsigned**, so Windows may show an unknown-publisher or SmartScreen
warning. A SHA-256 checksum is supplied with the release.

The build now supports signing whenever a certificate exists, with `-SignThumbprint` or a complete
`-SignCommand`. It signs the application binaries, the installer and the uninstaller, and refuses to
package anything that ends up unsigned.

## Verification

- **243/243 automated tests pass** on .NET 8.
- The FTS5 migration is tested against a database built in the exact shape 3.0.5 leaves behind,
  asserting the spots, the signing key and the search results all survive it.
- The cipher is pinned against ciphertext generated by the original code compiled for .NET Framework,
  in both directions.
- The script bridge behind the WebView2 spot page was run against a document built from the real
  comment template, covering the links, quoting, replying, posting and the author menu.
- Both the English and Dutch installer smoke tests pass end to end: fresh install, payload
  verification, shortcut replacement, upgrade backup, and an uninstall that keeps the profile.

## Known limitations

Native ARM64 and cross-platform support do not exist; WPF ties this to Windows. Performance work is
still waiting on a measurement from a real import.

Application version: **3.0.6.0**. This remains the community reconstruction based on Spotnet 2.0,
not an official upstream release.
