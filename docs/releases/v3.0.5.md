# Spotnet 3.0.5: fresh database hotfix

This patch fixes the first-run database error reported after entering news-server details in
a clean profile: `SQL logic error: no such table: spots`.

## Fixed

- A writable SQLite connection creates a non-empty database header immediately. Spotnet 3.0.4
  checked the file length only after opening that connection and therefore skipped creation of
  the core schema. Startup now inspects SQLite's schema directly.
- Profiles already affected by 3.0.4 are repaired automatically when they contain exactly the
  two auxiliary upgrade tables left by this bug. Existing rows in those tables are preserved.
- An unknown database that lacks the `spots` table is rejected instead of being overwritten.
- Index and trigger creation errors can no longer be ignored during startup.

## Install or upgrade

Download **Spotnet-3.0-x64-Setup.exe** and run it under your usual Windows account. Setup upgrades
an existing installer-based Spotnet 3.0 installation, keeps the profile, makes a verified backup
and updates current-user shortcuts.

Requires Windows 10/11 x64 and .NET Framework 4.7.2+. The package is **unsigned**, so Windows may
show an unknown-publisher or SmartScreen warning. A SHA-256 checksum is supplied with the release.

## Verification

- **180/180 automated tests pass** on the x64 Release host.
- Regression coverage recreates the real failure order: opening SQLite first, then initializing
  a fresh database.
- A second regression fixture verifies automatic recovery of a 3.0.4 partial database while
  preserving data; the safety test verifies unrelated tables are refused.

Application version: **3.0.5.0**. This remains the community reconstruction based on Spotnet 2.0,
not an official upstream release.
